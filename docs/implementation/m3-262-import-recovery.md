## 1. Fixture

The integration fixture is generated at runtime from a committed seed/version; no large
manuscript is committed and no model/provider call is made.

| Field | Value |
| --- | --- |
| Seed | `novelbrain-import-recovery-v1` |
| Version | `1` |
| Characters | `10,000,000` |
| Chapters | `1,000` |
| Characters per chapter | `10,000` |
| Characters per chunk | `250,000` |
| Chunks | `40` |
| SHA-256 | `8a6d4d6b55d18c062754e48657285a93dee8450498cd74e27215def7d1644497` |

The fixture is generated by `apps/api/test/helpers/large-manuscript.ts`. Assertions use
lengths, hashes, counts and source ranges; the test does not print manuscript text.

## 2. Recovery Evidence

`apps/api/test/manuscript-import-chunked.integration.test.ts` exercises the public HTTP
lifecycle:

- streamed start and sequential chunk append;
- bounded requests below 1 MB per chunk;
- partial upload failure and retry;
- idempotent pause/resume and process suppression while paused;
- app restart while processing, followed by continued processing from committed chunks;
- cancel and rejection of append after cancellation;
- repeated cancel, rejected confirmation after cancellation and cross-tenant denial;
- partial status when fewer chunks were uploaded than declared;
- range-only confirmation without sending 10M characters in one request;
- confirmation response below 200 KB, containing work metadata instead of chapter text;
- replay confirmation without duplicate chapters or versions;
- source ranges covering exactly `0..10,000,000`;
- rejection of a range that splits a surrogate pair.

Recorded local run:

| Metric | Value |
| --- | ---: |
| Elapsed | `55,930 ms` |
| Peak process RSS | `539,910,144 bytes` |
| Chunk request ceiling asserted | `< 1,000,000 bytes` |
| Processed chunks | `40 / 40` |
| Imported chapters | `1,000` |

The memory bound is for this fixture and environment, not a universal throughput or
capacity claim. The test fails if peak process RSS reaches 768 MiB.

## 3. Production UI Evidence

`apps/web/e2e/parity/new-project.spec.ts` covers the production `new-project` flow:

- one injected chunk-upload failure followed by real API retry;
- received/processed chunk progress;
- pause and resume while processing;
- metadata-only preview with server-retained source;
- range-based confirmation through the real API;
- four viewports: 390, 900, 1180 and 1440;
- no horizontal overflow.

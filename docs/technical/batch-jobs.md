# 批量创作上下文边界

批量创作按章节顺序执行，但同一批里的后续章节不会把前面的未审核草稿当成已确认事实。

- 每章仍走现有的上下文编译、起草、事实抽取和连续性检查。
- 已确认事实按作品分支读取，因此前一批已确认的内容会进入后续章节。
- 批次生成新章节时，会自动引用最近三章已锁定或已发布章节的正文作为参考。
- 审核队列的“批准”只锁定本章，不代替作者确认事实提案；事实确认继续沿用写作台的人工确认流程。
- 同一批中先生成、尚未审核的草稿不会被当作正史或后续章节的事实来源。

这样既避免批量任务绕过人工确认，也避免把同一批的未审核草稿误当成正史。

## 审批、风险与报告

- 审批方式保存在任务设置的 `approvalMode`：`chapter`、`volume`、`auto`，默认 `volume`。
- `auto` 在创建任务时校验三项门禁：标准质量档位、所选章纲全部锁定、章纲没有高风险关键词。
- 审核队列按连续性问题和质量报告给出 `low`、`medium`、`high` 风险等级。高风险包括连续性待处理问题、质量维度偏弱、关键人物死亡、金手指升级、改已确认设定等。
- `volume` 和 `auto` 会自动批准非高风险且非卷末的章节；`chapter` 全部等待作者确认。卷末和任何高风险章节始终留在审核队列。
- 低风险章节支持批量批准。送平行版本会新建独立创作线并写入这一稿，主创作线不写入正文，章状态回到计划中。
- 任务报告包含质量维度均分、未回收伏笔（含过期标记）和下一步建议；worker 与 API 读取时都会补齐这些字段。

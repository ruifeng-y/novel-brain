# M0 作者演示脚本

> 适用：M0 内部演示
> 预计时长：15–20 分钟
> 目标：从一句想法走到“本章事实已提交，已确认设定出现新内容”

## 演示前准备

1. 请技术同事运行 `pnpm stack:up`，确认 `http://localhost:3000/health` 显示运行正常。
2. 打开 `http://localhost:8025`，这是演示邮箱；注册验证码会出现在这里。
3. 准备一句仙侠想法：`一个被宗门抛弃的杂役，意外得到一本会吞噬记忆的古书。`

不要使用真实作者稿件或真实 API Key 做公开演示。演示 Key 只用于本地测试。

## 1. 注册并配置模型

1. 打开 `http://localhost:3000/register`。
2. 填写演示邮箱，点击“发送验证码”。
3. 在 Mailpit 打开最新邮件，复制 6 位验证码。
4. 填写显示名称和密码，点击“注册并进入”。
5. 进入“账号设置”，填写配置名称和演示 Key，勾选“正文”，点击“新增配置”。
6. 确认页面只显示 `****1234` 形式的掩码，点击“测试连接”。

预期：页面显示“连接正常。”，任何位置都不显示完整 Key。

## 2. 用一句想法开书

1. 打开“工作台”，点击“新建作品”。
2. 选择“一句话想法”。
3. 书名填写 `忘川书`，故事灵感填写上面的演示想法。
4. 点击“创建作品并进入总览”。

预期：进入作品总览，能看到“主创作线”、草稿状态和准备度。

## 3. 生成并锁定故事圣经

1. 打开“故事圣经”。
2. 点击“生成九卡提案”。
3. 检查九张卡都有内容，点击“锁定故事圣经”。

预期：页面提示故事圣经已锁定；九张卡进入只读状态。

## 4. 写本章章纲

1. 打开“大纲”。
2. 填写以下内容：
   - 章节序号：`1`
   - 章节标题：`一只手也能结印`
   - 章目标：`让沈砚在断臂后找到新的战斗方式，并让顾青第一次怀疑他。`
   - POV：`沈砚`
   - 地点：`荒寺外山道`
   - 场景节拍：`沈砚藏起断臂，被顾青撞见。`、`血河宗追兵逼近，两人被迫联手。`、`沈砚单手结印，忘川书短暂显形。`
   - 必用事实：`左臂骨折，不能双手结印`、`顾青不知道忘川书完整来历`
3. 点击“创建章纲”。

预期：页面显示“章纲已完整”，并出现“打开写作台”。

## 5. 准备三张基础设定

打开“设定中心”。每张卡都按同一流程操作：点击“新增设定”，选择对应类型，填写下列字段，点击“创建设定”，打开卡片详情，再点击“锁定设定”。

1. 世界规则
   - 名称：`天门只认完整记忆`
   - 摘要：`失去关键记忆的人无法通过天门。`
   - 世界规则：`主动抹除关键记忆会导致天门通行失败。`
2. 人物
   - 名称：`沈砚`
   - 摘要：`隐藏忘川书的外门杂役。`
   - 当前身体状态：`左臂骨折，不能双手结印。`
   - 知识边界：`不知道父母死于仇杀。`
   - 关系摘要：`与顾青互相试探。`
3. 金手指
   - 名称：`忘川书`
   - 摘要：`以记忆换取前人经验。`
   - 规则：`每次只能借用一位前人的经验。`
   - 代价：`永久失去一段重要记忆。`
   - 限制：`每次使用消耗一页。`
   - 成长：`缺失记忆会拼成完整人格。`

预期：三张卡都显示已锁定。

## 6. 生成一章并处理事实

1. 从章纲点击“打开写作台”。
2. 点击“生成整章”。
3. 等待生成进度到达 100%，确认页面显示正文、来源、费用和断点。
4. 在“本章事实”中：
   - 对一条低风险事实点击“驳回”。
   - 对高风险和中等风险事实各点击一次“确认”。
5. 点击“批准本章”。
6. 点击“提交本章事实”。

预期：先看到“本章已批准”，再看到“本章事实已提交”和“摘要已更新”。

## 7. 查看结果

1. 返回“设定中心”。
2. 点击“查看已确认设定”。

预期：页面出现“章节事实”，内容来自刚提交的两条必用事实。驳回的事实不会出现。

## 演示失败时

- 没有验证码：检查 Mailpit 是否启动，并重新点击“发送验证码”。
- 模型测试失败：确认演示 Key、网络和 DeepSeek 官方地址；不要继续使用错误 Key。
- 生成按钮不可用：依次检查模型配置、故事圣经锁定、三张基础设定锁定和完整章纲。
- 提交按钮不可用：先确认必用事实已确认，再批准本章；三个动作不能合并。

# NovelBrain V1 需求基线

> 状态：V1 基线（已同步 ADR 0010–0027）
> 版本：v0.5
> 日期：2026-11-04
> 适用范围：V1 首个可开发版本
> 说明：本文件记录 V1 已确认的产品需求和主要风险。

## 0. 文档说明

### 0.1 目标

把已经讨论过的产品需求固化成可评审、可拆 Issue、可进入技术设计的基线。

### 0.2 使用方式

- 已确认内容作为 V1 开发依据。
- 术语含义见根目录 `GLOSSARY.md`。
- 本文不记录具体技术实现，技术选型单独成文。

### 0.3 V1 Baseline Freeze

以下裁决优先于本文旧条款；冲突时以 ADR 和 `docs/planning/v1-capability-manifest.md` 为准。

- 容量：1000 万字、3000–4000 章、30–40 卷；每卷 80–120 章，每章 2500–3500 字。
- 质量：目标为白金级；V1 按 ADR 0010 的可测量门槛验收，不把主观“白金”当唯一验收口径。
- 导入：默认文本导入只解析、切分、保留原文；可选“设定提取”才做候选抽取和冲突确认。
- UI：设定中心固定 7 个顶层栏目；V1 只做仙侠、历史、都市；状态枚举以本文 14.1 为准。
- 门禁：章节批准不等于事实提交；事实必须单独确认；高风险冲突不可绕过。
- 安全：BYOK 仅允许白名单 Provider；HTTPS、SSRF 防护、RLS、日志脱敏、删除 SLA 按 ADR 0014 执行。
- 成本：不做平台配额；单章/单卷/每 1 万字成本可配置上限，超限暂停，不静默降级。
- 范围边界：V1 是个人作者工作区，不包含多人同章实时协同编辑或完整经济交易引擎；两者作为 post-V1 能力保留，见 ADR 0025–0026 和 `docs/planning/post-v1-scope-register.md`。
- 细化裁决：单一版本图、审核状态机、导入分块、一等领域模型、选择性摘取、父子卷章任务、质量与安全门禁见 ADR 0016–0023。

## 1. 产品定位

### 1.1 一句话定位

面向非专业个人作者的 AI 长篇小说创作平台，把作者的一个想法或部分设定，变成可连载、可修改、可回滚的长篇作品。

### 1.2 目标用户

- 没有完整写作经验，但有故事想法的个人作者。
- 想完成第一本书、尝试连载、或验证自己创意的作者。
- 不需要团队协作、项目管理或复杂权限的个人创作者。

### 1.3 核心价值

- 引导式创作：作者不需要理解 AI、Agent、正史、上下文编译这些内部概念。
- 长线一致性：用世界事实、角色认知、叙事计划、文本四层状态支撑百万字级作品。
- 可控修改：先提案、再影响分析、再确认；大修改拉平行版本，不悄悄改历史。
- 可规模化：架构基线按 1000 万字设计，首个质量样片先做 10 到 15 万字。

### 1.4 产品原则

- 前台只说作者语言，后台隐藏内部实现。
- 作者是最终决策者，AI 只生成提案。
- 已写内容不悄悄改，大修走平行版本。
- 设定是数据库，不是提示词；相关设定必进上下文，输出必用全量设定校验。
- V1 不做团队、管理员后台、配额、计费、本地模型。
- 不以生成字数作为成功标准，以完成第一卷和持续连载作为成功标准。

## 2. V1 范围

### 2.1 V1 做

- 邮箱验证码注册、登录、找回密码。
- 个人账号、多作品、多分支。
- 仙侠、历史、都市三个题材方向。
- 历史方向先做架空古代或穿越争霸，不做严格真实历史。
- 故事圣经、设定中心、大纲与剧情、写作台、批量生产、修改与版本、导出。
- 每人自带云端模型 API Key，平台不代付、不做配额。
- 数据隔离、备份、导出、注销。

### 2.2 V1 不做

- 团队、成员、邀请、角色矩阵及多人同章实时协同编辑（post-V1，见 ADR 0025）。
- 管理员后台、产品内 admin 角色。
- 配额、计费、充值、在线支付。
- 本地模型、Ollama、vLLM、模型微调或训练。
- 完整经济交易引擎：多世界货币账户、动态定价、供需/生产/交易结算、资产市场和经济事件账本（post-V1，见 ADR 0026）。
- 直连起点或番茄发布。
- 分享链接、公开作品、读者社区。
- 移动端原生 App。
- 定时日更、邮件通知。
- PDF 导出、AI 封面。

## 3. 用户与账号

### 3.1 注册与登录

- 使用邮箱注册。
- 注册流程：输入邮箱、发送邮箱验证码、填写验证码、设置密码、完成注册。
- 注册成功后不要求二次邮箱验证链接。
- 验证码发送限频：同一邮箱和 IP 每分钟最多一次，设置每日上限。
- 验证码错误次数过多时增加等待时间。
- 登录方式：邮箱加密码。
- 会话使用 httpOnly Cookie，支持退出所有设备。
- 找回密码：云端走邮件链接；局域网部署可通过运维 CLI 重置。
- 本需求按“邮箱验证码”理解，不是图形验证码。

### 3.2 账号资料

- 账号包含显示名、笔名、头像、简介。
- 一个账号可以有多个笔名。
- 每部作品选择一个笔名。
- 修改邮箱需要验证新邮箱。
- 修改密码需要验证旧密码。

### 3.3 账号生命周期

- 状态：正常、禁用、注销中、已注销。
- 禁用由部署运维通过 CLI 执行，不做产品内后台。
- 注销账号需要二次确认。
- 注销前必须完成数据导出。
- 账号和作品保留 30 天可恢复，30 天后永久删除。
- 支持一键导出全部作品、设定、大纲和修改记录，导出包不包含模型 API Key。

### 3.4 身份与权限

- V1 只有普通用户，没有产品内管理员角色。
- 部署运维通过环境变量和 CLI 完成：初始化数据库、开关注册、重置密码、备份恢复、健康检查。
- 运维默认不能通过产品界面查看作者作品和 Key。
- 用户只能访问自己的账号、作品、分支和数据。

## 4. 模型接入

### 4.1 接入方式

- 每个用户在自己的设置中配置云端模型 API。
- V1 只允许 DeepSeek 官方和显式加入白名单的 OpenAI 兼容 Provider；自定义 Base URL 必须 HTTPS，禁止私网、回环、链路本地地址和重定向。
- 填写 Base URL、API Key、模型名。
- 可保存多套模型配置。
- 规划、正文、检查可以分别选择模型。
- 至少保留一套默认配置。
- 提供“测试连接”。

### 4.2 安全与错误

- API Key 加密存储，界面只显示掩码。
- 保存后不再向前端返回明文。
- 日志必须脱敏，运维不可见。
- Key 无效、余额不足或被限流时，生成任务停止并提示。
- 不自动切换到平台 Key，不退化为本地模型。

### 4.3 用量与保护

- 显示 token 用量和预估费用。
- 不做平台配额、不做计费、不做管理员调额。
- 防跑飞保护：单章最大输出 token、单章最大重试次数、批量任务最大章节数、单章/单卷/每 1 万字成本上限；超限暂停，不静默降级。

## 5. 作品与项目生命周期

### 5.1 创建入口

- 一句话想法。
- 部分设定或完整设定导入。
- 空白作品。
- 题材模板。
- 导入已有稿件。
- 导入支持 TXT、Markdown、DOCX，按章节切分，保留原文。
- 默认“文本导入”不做全自动人物和设定抽取；作者可以显式发起“设定提取”，生成候选、冲突和导入报告后再确认。

### 5.2 作品信息

- 书名、笔名、题材包、目标平台、目标读者、规模。
- 章节字数、更新节奏、风格样本、禁忌、简介、标签。
- 封面 V1 支持上传，不做 AI 封面。

### 5.3 作品状态

- 筹备中。
- 连载中。
- 暂停。
- 已完本。
- 已归档。
- 状态影响列表筛选和默认操作，不硬锁内容。
- 内容锁定由章节状态和正史状态控制。

### 5.4 归属与共享

- 作品属于账号。
- 作品默认私有。
- V1 不做分享链接，不转让作品。

### 5.5 删除、归档与恢复

- 删除为软删除，保留 30 天可恢复。
- 永久删除前必须导出。
- 删除作品时一并处理分支、版本、快照和导出文件。
- 归档不等于删除。
- 归档作品默认不出现在作品列表，可恢复。

### 5.6 完本后修改

- 已完本作品默认只读。
- 要修改，拉平行版本，或重新开启为连载中。
- 避免直接修改已发布正文。

### 5.7 复制作品

- 复制故事圣经、设定、大纲和风格样本。
- 默认不复制正文，也不复制章节版本。
- 复制后生成一个新的独立作品。

### 5.8 作品列表

- 支持搜索。
- 按状态、题材、最近编辑、字数筛选。
- 显示进度、字数、最后编辑时间、质量分、未回收伏笔数。

### 5.9 作品级设置

- 笔名、题材包、目标平台、目标读者、规模。
- 章节字数、更新节奏、风格样本、禁忌。
- 模型配置放在账号级，不放在作品级。

## 6. 设定中心

### 6.1 总原则

- 设定中心由核心本体、题材包、关系图和状态历史组成。
- 顶层栏目固定为：世界、势力、人物、地图、力量体系、物品功法、时间线。
- 题材包子类放在栏目内部，不新增顶层栏目。
- 前台不出现“正史”等内部词，使用故事圣经、设定集、人物档案、时间线、伏笔清单、已确认设定。

### 6.2 设定条目

- 每个条目包含：名称、别名、类型、一句话摘要、详细描述、标签。
- 包含所属作品、作用域、状态、来源、关系、自定义字段、版本历史。
- 状态：草稿、提案、锁定、废弃。
- AI 生成的条目默认是提案，作者确认后才进入正史。

### 6.3 自定义字段

- 项目级支持自定义字段。
- 类型：文本、长文本、数字、日期、单选、多选、布尔、关系引用。
- 题材包提供默认字段。
- 高级模式可以新增字段。
- 新增字段不能破坏已有字段和数据。

### 6.4 关系

- 关系必须类型化，例如隶属、位于、控制、拥有、知道、相信、亲属、敌对、师承。
- 关系带有效期和来源。
- 提供关系图视图。
- 不使用自由文本关系。

### 6.5 地图与势力

- 支持分层地图树、地点节点、连接边、旅行时间、势力控制区。
- 支持上传地图图片并添加标记点。
- V1 不做自由绘制地图。
- 势力通过控制或存在关系挂到地点，带时间有效期。
- 角色不能同时出现在两个地点；移动时间必须足够。

### 6.6 人物与状态

- 人物档案分三层：基础档案、关系与弧光、当前状态。
- 当前状态包括身体状态、知识状态、力量状态、所在地、持有物、伪装。
- 知识状态必须区分客观真相和角色以为的真相。
- 声纹由对话样本和风格提示组成。
- V1 不做声音克隆。

### 6.7 力量体系与物品功法

- 通用模型包括层级、路径、突破条件、代价、瓶颈、克制、资源。
- 仙侠显示修炼体系。
- 历史显示武道或军制。
- 都市显示异能或资源体系。
- 具体由题材包决定，平台不写死。
- 金手指放在人物或力量体系里，必须有规则、代价、限制、成长曲线。
- 物品功法单独分类，记录品阶、效果、代价、归属和限制。

### 6.8 时间线与世界规则

- 时间线使用统一的故事时间模型。
- 支持纪元、绝对日期、相对时间、持续时长和事件节点。
- 世界规则使用结构化条目加自然语言约束。
- V1 不做通用逻辑引擎，只做上下文约束和校验提示。

### 6.9 状态、修改与体检

- 设定状态：草稿、提案、锁定、废弃。
- 锁定设定要改，必须走修改请求和影响分析。
- 设定体检先做基础检查：必填字段缺失、重名、断链关系、地图与势力冲突、时间线缺口、力量体系缺口。
- V1 不做完整语义证明。

### 6.10 AI 生成与使用

- 支持整套生成、单个生成、补全缺失字段、按想法改写。
- 输出都是提案，作者确认后才落正史。
- 支持全局搜索、按类型和标签筛选。
- 支持查看被哪些章节和大纲引用。
- 支持导出设定附录。

## 7. 大纲与剧情结构

### 7.1 五层结构

全书总纲包含：主题、核心冲突、结局方向、主线、支线、人物弧、分卷节奏、力量成长、地图和势力推进、伏笔总表。

卷纲包含：本卷目标、核心冲突、反派、地图区域、新出场人物、力量层级、关键事件、卷末高潮、卷首钩子、伏笔埋设和回收。

幕纲包含：每卷三到五幕，写清目标、阻碍、转折、高潮、收束和人物弧光节点。

章纲包含：章目标、POV、场景列表、冲突、爽点、信息释放、章末钩子、字数目标、出场人物、地点、时间、必须埋设或回收的伏笔。

场景卡包含：场景目标、POV、地点、时间、参与者、冲突、转折、信息释放、过渡。

V1 章级节拍必做，场景卡作为高级模式可选。

### 7.2 剧情线账本

- 类型：主线、支线、人物线、势力线、世界线、悬疑线、感情线。
- 每条线记录名称、摘要、赌注、参与者、开始节点、关键里程碑、计划兑现、实际兑现、状态、张力曲线、关联章节。
- 检查未收束的线、被遗忘的线、没有赌注的线、同时活跃的线太多。

### 7.3 伏笔账本

- 记录线索内容、埋设章、计划回收章、状态、重要程度、关联人物和势力、读者承诺。
- 区分必须回收和可选回收。
- 检查过期未回收、没有埋设就回收、重复线索、回收力度不够。

### 7.4 人物弧光账本

- 每个核心人物记录起点状态、欲望、恐惧、谎言、真相、关键转折、终点状态。
- 按卷拆分人物弧光节点。
- 检查核心人物有没有弧光、转折有没有排期、弧光有没有收束、动机有没有断点。
- 弧光计划放在大纲里，人物当前状态放在设定中心。

### 7.5 节奏与读者承诺

- 章级记录爽点类型、情绪目标、章末钩子、期待感、信息差。
- 卷级记录卷首钩子、升级节点、打脸、反转、收获、卷末高潮。
- 检查连续动作或连续日常、重复桥段、长时间没有兑现、钩子密度过低。
- 黄金三章单独做开篇策略：第一钩子、主角出场、世界规则展示、第一个爽点、三章章末钩子。
- 检查大纲有没有兑现故事圣经里的读者承诺。

### 7.6 编辑、锁定与分支

- 支持拖拽调整、节点级重生成、锁定和解锁。
- 未写区可自由改。
- 进行区强校验。
- 已写章节的大纲锁定。
- 锁定大纲要改，必须走修改请求和影响分析。
- 可以从任意节点拉平行版本，支持并排比较和选择性摘取。
- 正文写完发现和章纲不一致时，系统提取实际结果，生成大纲更新提案，作者确认后同步。
- 结局方向建议单独锁定，细节可改。

### 7.7 生成前置条件

- 全本生成要求全书总纲和分卷总纲已确认。
- 按卷生成要求本卷卷纲已确认。
- 按自定义区间生成要求对应章纲已确认。
- 生成前显示准备度检查：大纲完整度、设定健康度、连续性风险、模型 Key 是否可用、预计 token 和耗时。
- 准备度不够时列出缺什么，并提供补齐入口。

### 7.8 剧情体检

- 检查未收束剧情线、过期伏笔、剧情漏洞、人物动机断点、反派降智、战力膨胀、重复桥段、地图和时间矛盾、信息越界、节奏塌陷。
- V1 用基础规则加模型评审，不做完整逻辑证明。
- 支持章级、卷级、全书级体检，输出严重程度和受影响节点。

### 7.9 视图与导出

- 视图先做树状大纲、章节看板、张力曲线、剧情线账本。
- 时间线视图复用设定中心。
- V1 导出支持 TXT、Markdown、DOCX、EPUB；PDF 后续再加。
- JSON 只作为内部备份/调试格式，不作为作者发布格式。

## 8. 章节生成与写作台

### 8.1 核心原则

- 写作台只负责写正文，不直接改设定。
- 正文里的新事实由系统提案，作者确认后才进正史。
- 要改设定，走修改请求，不在正文里偷偷改。

### 8.2 布局

- 左侧：章节列表、卷导航、状态、搜索。
- 中间：章节标题、正文编辑器、工具栏、字数、自动保存。
- 右侧：编辑建议、连续性、伏笔、人物状态、本章设定。
- 顶部：生成、续写、重写、检查一致性。
- 底部：字数、阅读时长、保存状态、模型、token 用量。
- 提供专注模式，隐藏两侧面板。

### 8.3 生成粒度

- 整章生成。
- 从光标续写。
- 选中段落重写。
- 扩写、缩写。
- 改视角。
- 加章末钩子。
- 生成三个章末钩子版本。
- 生成章节标题和摘要。
- V1 支持场景卡和场景节拍；按场景单独生成后续再加，但章节生成必须按场景节拍执行。

### 8.4 生成控制

- 质量档位：快速、标准、精品。
- 模型配置可按规划、正文、检查分别选择。
- 支持字数目标、POV、必须包含、必须避免、参考章节、禁忌词。
- 风格控制先做三个滑杆：克制到热烈、快到慢、白描到华丽。
- 高级参数不暴露给非专业作者。

### 8.5 编辑批注

- 正文行内批注：连续性问题、人物声纹、节奏、重复、套路化、逻辑问题。
- 右侧章级建议：钩子够不够、哪里水了、下一章读者会想看什么。
- 默认每章最多三到五条，避免干扰。
- 每条可以接受修改、让 AI 重写、要求解释；低风险误报可以忽略并记录原因，高风险冲突不能忽略。

### 8.6 章节状态与版本

- 章节状态固定为：已规划、写作中、待审、要求修改、已批准、已锁定、已发布、已驳回。
- “批准章节”只表示正文通过审核，不等于事实进入故事事实库。
- 自动保存，带本地恢复。
- 每次生成和手动修改都留版本，可以看差异、恢复旧版。
- 小修原地改并留版本。
- 中修给影响报告。
- 大修改正史或已锁章节，必须走修订或平行版本。

### 8.7 事实抽取与正史提交

- 抽取事件、身体状态、角色认知、位置、力量、物品、关系、剧情线、时间线。
- 作者在“本章事实”面板里确认、修改或驳回。
- 事实提案状态固定为：已提案、已确认、已修改确认、已驳回、已替代。
- 只有“已批准/已锁定章节 + 已确认事实”或满足自动通过条件，才能执行故事事实提交；提交后更新摘要和索引。
- 默认逐项人工确认；只有满足自动通过条件且不属于“永远人工确认”的事件，才允许自动提交。

### 8.8 连续性与质量检查

- 检查大纲贴合、正史冲突、时间线、身体状态、知识边界、战力、地图移动、势力关系、物品归属、POV、重复和 AI 腔。
- 问题在正文里高亮，右侧给修改建议。
- 低风险误报可以忽略并记录原因；高风险冲突必须修订、拒稿或拉平行版本。
- 章级质量报告用钩子、节奏、信息密度、人物声纹、文笔、连续性六项。

### 8.9 与批量生产的分工

- 写作台负责单章精修，人工介入多，控制细。
- 批量生产负责多章、按卷、自定义区间和全本，带审批、暂停、恢复和失败隔离。
- 两者共用同一条章节流水线。
- 批量任务可以随时把某一章送回写作台人工处理。

## 9. 批量生产与任务中心

### 9.1 任务类型

- 生成章节。
- 重写或修订章节。
- 事实回填。
- 连续性审计。
- 卷级审计。
- 全书审计。
- 大纲生成留在纲工作台，不放进任务中心。

### 9.2 生成范围

- 按章。
- 按卷。
- 自定义区间。
- 全本。
- 按章可以后台跑，也可以直接在写作台写。
- 自定义区间必须连续，并且前面的章节已经提交正史；有缺口就提示补齐，或者只生成不入正史的草稿。
- 全本按卷拆成子任务，不一次跑完。

### 9.3 审批方式

- 逐章审批。
- 逐卷审批。
- 自动通过。
- 默认逐卷审批。
- 自动通过只允许在大纲已锁定、标准质量、无高风险时使用。
- 卷末仍然要人工确认。
- 关键人物死亡、金手指升级、改已锁定正史、分支合并，永远需要确认。

### 9.4 任务流水线

准备度检查、章 brief、上下文编译、起草、自检、修订、事实抽取、一致性检查、人工审核、正史提交、摘要和索引更新。

任务详情显示当前章节、完成数、token、预估费用、错误和决策记录。

### 9.5 并发与正史提交

- 草稿可以并行，正史提交必须串行。
- V1 默认顺序生成，优先保证一致性。
- 架构上预留“草稿在前、正史提交在后”的波次模式。
- 同一分支只能有一个正史写入者。
- 不同分支互不影响。

### 9.6 暂停、恢复、取消、重试

- 暂停在当前步骤结束后生效。
- 恢复从检查点继续。
- 取消停在当前章节，已完成章节保留，剩余标记取消。
- 失败从失败步骤重试，不从头再来。
- 单章失败可以继续下一章，也可以设置失败即暂停。
- 正史提交失败必须停止后续提交。

### 9.7 准备度与防跑飞

开始前检查：大纲是否确认、设定健康度、正史版本、前序章节是否提交、模型 Key 是否可用、预计 token 和耗时、未解决冲突、章节数。

准备度不够就列出缺什么，并给补齐入口。

不做平台配额，但保留安全上限：单任务最大章节数、单章最大输出 token、单章最大修订次数、最大重试次数、单章/单卷/每 1 万字成本上限；超限暂停，不静默降级。

Key 失效、余额不足、连续失败、连续性错误率过高、高风险正史冲突时自动停止。

### 9.8 审核队列与任务报告

- 审核队列显示待确认章节、质量、连续性问题和建议。
- 可以批准并锁定、送写作台修改、驳回重生成、送平行版本；低风险问题可以忽略并记录原因，高风险问题不可绕过。
- 低风险章节可以批量批准。
- 高风险必须逐章看。
- 任务结束后出报告：完成和失败章节、token 和费用、连续性错误、质量摘要、未回收伏笔、下一步建议。
- 任务历史保留日志。

### 9.9 全本生成与通知

- 全本生成采用父任务加卷子任务。
- 默认在卷边界暂停。
- 每卷结束做一次审计。
- 开始前给出总 token、总耗时和费用预估。
- V1 只做手动任务和站内通知。
- 定时日更和邮件通知后续再加。

## 10. 修改、影响分析与平行版本

### 10.1 修改类型

- 设定修改：世界、势力、人物、地图、力量体系、物品、时间线、规则。
- 大纲修改：全书、卷、幕、章、场景。
- 正文修改：章节、段落、句子。
- 正史事实修改：已确认事实、角色认知、剧情线、伏笔。
- 平行版本操作：创建、比较、摘取、合并。
- 作品级修改：书名、笔名、题材包、规模、风格、禁忌。

### 10.2 修改请求

- 每次修改生成一个修改请求。
- 包含：标题、原因、目标、旧值、新值、差异、来源、风险等级、状态。
- 来源：作者直接改、AI 提案、导入、批量任务。
- 改正史、改大纲、改作品级设置必须填原因。
- 纯文字润色可以不填原因。
- AI 修改一律是提案，作者确认后才应用。

### 10.3 影响分析

- 计算修改会影响哪些实体、事实、章节、大纲、剧情线、角色认知、地图和势力关系、战力物品、时间线。
- 结果分三类：安全、可修复、结构性冲突。
- 列出受影响章节、冲突类型和建议改法。
- 给出置信度和理由。
- 大范围修改放到后台任务里跑。

### 10.4 一致性检查

- 结构校验。
- 硬规则校验。
- 事实差异。
- 知识和视角校验。
- 叙事校验。
- 下游影响分析。
- 输出通过、警告或冲突，并给修改建议。
- 低风险误报可以忽略并记录原因；高风险冲突必须修订、拒稿或拉平行版本。

### 10.5 三区与小修、中修、大修

- 已写区锁定，不能原地大改。
- 进行区可以改但强校验。
- 未写区自由改。

小修是错别字、标点、纯文字润色，不改变事实，可以原地改并留版本。

中修是改变事实但不破坏下游，走影响报告和重新校验。

大修是改正史、改已锁定章节、影响已写内容，必须拉平行版本或走明确修订。

已发布章节和已锁定正史不能原地覆盖。

### 10.6 平行版本

- 可以从任意版本点拉平行版本，支持整本或从某一章开始。
- copy-on-write，不复制全文。
- 平行版本有名称、原因、父版本、分叉点和状态。
- 类型：重写、What-if、另一个结局、实验。
- 可以并排比较设定、大纲和正文，冲突高亮。
- V1 不做自动合并，只做选择性摘取。
- 把分支里的某一章、某个设定、某段大纲带回主线，仍然走修改请求和影响分析。
- 分支可以归档和删除，删除前要确认。

### 10.7 版本与回滚

- 每次修改都产生新版本，历史不可删除。
- 版本结构是图，不是一条线。
- 章节、卷、正史提交都有快照。
- 单次修改可以撤销，系统生成反向修改并重新校验。
- 整条分支可以回滚到某个版本点，回滚本身也产生一个新版本。
- 回滚会同时恢复该分支的设定、大纲、正文和正史，作者确认后生效。

### 10.8 修改中心与审计

- 修改中心列表支持按类型、状态、风险、日期筛选。
- 详情页显示差异、原因、影响范围、校验结果、决策记录。
- 提供影响地图、版本图、并排比较。
- 审计记录包含谁、什么时候、改了什么、为什么改、影响了什么、校验结果、最终决策。
- 审计可以导出。
- V1 只有作者本人确认，没有角色审批、评论和管理员。

### 10.9 AI 辅助修改

- AI 只生成提案和差异，不能直接应用。
- 修改原因提供预设选项：修复矛盾、增强动机、调整节奏、读者反馈、实验、其他。
- 影响分析和全书回滚开始前显示预计 token 和耗时；超过已配置的单次成本上限时暂停并等待作者确认，不静默执行。

## 11. 导出、发布与数据安全

### 11.1 导出

- 格式：TXT、Markdown、DOCX、EPUB。
- PDF 后续再加。
- 范围：当前章、选中章节、自定义区间、整卷、全本、指定平行版本。
- 可选择是否附带故事圣经、设定附录、大纲、伏笔账本和修改记录。
- 支持导出某个历史版本，并在文件里带版本清单。
- 平台预设：通用网文、起点、番茄。
- 可配置章节标题格式、卷标题、段落空行、首行缩进、编码。
- 编码统一 UTF-8。
- 导出前可以预览前几章和目录结构。
- 小文件直接下载，大文件走后台任务并显示进度。
- 保留导出历史，可以重新下载。
- 导出文件默认保留 7 天，过期后可以重新导出。
- 单章支持复制到剪贴板。

### 11.2 发布

- V1 只做导出，不直连起点或番茄。
- 提供书名备选、简介、标签、章节名建议。
- 提供读者预览模式。
- 提供发布检查清单。
- 不绑定平台账号，不做自动上传。

### 11.3 发布检查

- 书名、简介、标签、题材、封面是否齐全。
- 前三章钩子是否达标。
- 章节字数是否符合平台习惯。
- 有没有敏感词和违规内容。
- 是否需要 AI 生成内容标识。
- 有没有版权和原创性提醒。
- 导出格式是否正确。

### 11.4 账号与密钥安全

- 注册验证码限频。
- 密码用 Argon2id 哈希。
- 会话用 httpOnly Cookie，支持退出所有设备。
- 登录和导出限流。
- 模型 API Key 用信封加密存储。
- 界面只显示掩码，保存后不再返回明文。
- 日志必须脱敏，运维不可见。
- 每个用户只能看到自己的 Key。
- 封面和地图图片限制大小和格式，重新编码后存储，避免脚本注入。

### 11.5 数据隔离、备份与恢复

- 每个用户的数据按用户隔离。
- 数据库行级安全，所有故事表启用 RLS，并以 `app.user_id` 作为租户上下文。
- 对象存储按用户前缀，下载用签名链接。
- 传输走 TLS，数据库和备份加密。
- 每天自动备份数据库和对象存储，保留 30 天。
- API Key 加密保存、界面掩码、日志永不记录；正文和 prompt 不写普通日志，追踪服务默认关闭或自托管。
- 注销 30 天后硬删除作品、正文、版本、正史、上下文包和轨迹；备份在 30 天内过期，不保留孤儿数据。
- 定期做恢复演练。
- 日志不记录正文和 Key，保留 30 天。
- 审计记录登录、Key 变更、导出和删除。

### 11.6 隐私、合规与删除

- 明确告知用户正文会发送给所选模型供应商。
- 平台不用用户作品训练模型。
- 优先选择不训练、低保留的供应商。
- 提供隐私政策、用户协议和 AI 生成内容标识说明。
- 注销账号前必须导出。
- 账号和作品保留 30 天可恢复，之后永久删除。
- 支持一键导出全部作品、设定、大纲和修改记录，导出包不包含 Key。
- 国内合规先按公开运营准备：内容审核、AI 生成内容标识、生成式 AI 备案评估。
- 私有部署时责任会部分转移给部署方，需要法务确认。
- 版权上明确用户拥有作品，平台只获得存储和处理所需的有限授权。
- 不拿起点正文做训练。

## 12. V1 验收标准

> 本节定义 V1 整体验收标准。每张 ticket 的验收标准由 `to-tickets` 生成，但不能低于本节的产品级门槛。

### 12.1 功能验收

- 需求文档第 1 到 11 节的每条需求，都能映射到至少一张 ticket。
- 每张 ticket 都有可执行的验收标准，不能只写“实现某功能”。
- 每个里程碑都有 demo 和 gate。
- M0：注册、建作品、配 DeepSeek Key、最小仙侠故事圣经、生成一章、事实确认，内部演示。
- M1：仙侠完整创作闭环，故事圣经、设定中心、大纲、写作台、连续性检查可用，可内部连载。
- M2：历史、都市题材包、批量生产、任务中心、修改影响分析和平行版本可用。
- M3：导出、发布检查、数据安全、性能、合规和 V1 总验收通过。
- 所有 P0 和 P1 缺陷关闭，没有已知数据丢失问题。

### 12.2 质量验收

- 接入真实读者数据后，盲评至少 10 名目标读者，至少 70% 愿意追读前三章；V1 用作者确认和模型评审代理，不把真实读者数据作为硬门槛。
- 章末钩子平均不低于 4/5。
- 连续性硬伤不超过每 5 万字 1 个，V1 验收时不能有未解决的关键矛盾。
- 大纲贴合度不低于 90%。
- 标记为“必须回收”的伏笔，回收率不低于 90%。
- 抽样章节的人物声纹、重复度和 AI 腔通过人工评审量表。
- 抽样章节按 ADR 0010 的白金级可测量门槛验收：P0 事实丢失 0、知识边界违规 0、大纲贴合度 ≥90%、钩子/文笔 ≥4/5、目标读者追读率 ≥70%（有真实读者数据后启用）、连续性冲突 ≤1/5 万字。

### 12.3 非功能验收

- 1000 万字、3000–4000 章作品能正常打开、搜索和编辑。
- CRUD 接口 p95 小于 300ms，搜索 p95 小于 1 秒。
- 流式首 token 小于 5 秒，SSE 事件延迟小于 1 秒。
- 单章 2500–3500 字，目标 ≤5 分钟；单卷 80–120 章可按 overnight 批处理；3000–4000 章按卷推进并支持断点恢复。
- 每日备份，RPO 24 小时，RTO 4 小时，并且做过恢复演练。
- 密码、会话、模型 Key、限流、审计和日志脱敏通过安全检查。
- 支持 Chrome、Edge、Safari 最近两个大版本，响应式 Web，不做原生 App。
- 局域网 Docker Compose 和单机云 VM Docker Compose 能完整启动；MinIO、SMTP 或 Mailpit 可用；托管云服务后续。

### 12.4 发布门槛

- M0 只做内部演示，不对外发布。
- M1 可以内部 beta，仙侠题材可连载。
- M2 可以扩大 beta，多题材、批量、修改版本可用。
- M3 才是 V1 正式发布，必须通过功能、质量、非功能、安全和恢复验收。
- 每次发布前检查：迁移、备份、监控、文档、回滚方案。

### 12.5 Definition of Done

- 所有 V1 ticket 完成。
- 所有 ticket 验收标准通过。
- 所有里程碑 gate 通过。
- 没有 P0 和 P1 缺陷。
- Vitest、Playwright、集成测试全部通过。
- 文档、迁移、备份和回滚方案更新。
- 代码评审完成，发布说明写好。

## 13. 风险

### 13.1 主要风险

- 质量上限：模型能否稳定写出接近白金级的文本。
- 长线一致性：1000 万字下上下文、正史和校验是否可靠。
- 成本：高质量生成和多次评审的 token 成本。
- 模型供应商稳定性、限流和条款变化。
- 国内合规、内容审核和 AI 标识要求。
- 版权和原创性争议。
- 非专业作者的留存和完成率。
- 范围膨胀：三题材、复杂设定和版本系统同时做。

## 14. 附录

### 14.1 状态机

作品状态：筹备中、连载中、暂停、已完本、已归档。

章节状态：已规划、写作中、待审、要求修改、已批准、已锁定、已发布、已驳回。

修改请求状态：草稿、分析中、等待确认、应用中、已应用、已驳回、已取消、已失败、已拉分支。

任务状态：排队中、准备中、运行中、已暂停、等待审核、已完成、已失败、已取消。

设定状态：草稿、提案、锁定、废弃。

导入状态：排队中、解析中、抽取中、等待确认、已完成、部分失败、已取消。

分支合并状态：草稿、比较中、等待逐项确认、应用中、已完成、已失败、已取消。

# NovelBrain V1 总验收记录

> 结论：**V1 不能按需求基线第 12 节正式公开发布。**
>
> 自动化功能门禁、性能门禁、代码级安全检查和恢复演练在确定性 fake provider
> 的干净 Compose 环境中通过；但质量门禁、真实 DeepSeek、账号生命周期、审计、
> 完整导出、TLS/静态加密/日志保留、浏览器覆盖和法务确认仍未闭环。当前版本
> 可作为 V1 发布候选用于局域网/内部验收，不得标记为 V1 正式发布版本。

## 范围

本记录覆盖 GitHub issue #33「M3-06 V1 总验收」：

- 需求基线第 12 节功能、质量、非功能、发布门槛和 Definition of Done。
- issue #1 的 V1 spec 与 user stories。
- issue #2 到 #32 的交付 ticket 和 M0/M1/M2 验收记录。
- M3-01 到 M3-05 的导出、发布检查、数据安全、性能、合规证据。
- 干净 Compose 环境下的 lint、typecheck、Vitest、Playwright、build、压测、
  安全测试、备份和恢复演练。

## 已知限制与未验证项

详见 `docs/release/v1-known-limitations.md`。最重要的边界是：

- 所有自动验收使用确定性 fake provider，不调用真实 DeepSeek。
- 3M 字、CRUD、搜索、SSE 和并发是单机 Windows Docker Compose 实测；不是云环境、
  多区域或多用户生产压测。
- 质量验收、读者盲评、人工声纹/AI 腔评审没有执行。
- Chrome/Chromium 以外的浏览器、TLS、静态加密、生产 SMTP、异地备份和日志平台
  未验证。
- 部分作品级资料字段、大纲独立导出、历史版本导出等需求缺口仍未实现。

## 最终结论

**V1 不是真正可公开发布的状态。**

可以说：

- M3 的导出、发布检查、代码级安全、性能、恢复演练和本地发布候选门禁通过。
- M0-M2 的历史创作闭环仍通过全量回归。
- 当前构建适合局域网/内部发布候选验收。

不能说：

- V1 已通过需求基线第 12 节全部验收。
- 没有 P0 和 P1。
- 真实 DeepSeek 文本质量、延迟、费用和稳定性已达到发布门槛。
- 已具备公开运营所需的账号生命周期、完整审计、完整导出、TLS/静态加密/日志保留
  和法务合规。

在 B-01 到 B-08 关闭前，不应把本分支标记为 V1 正式发布，也不应关闭 #33 或推送
为正式 release。

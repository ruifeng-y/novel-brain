# 千万字使用分层上下文与记忆

千万字无法靠超长上下文解决。我们建立分层记忆：故事圣经、卷/幕摘要、章摘要、场景卡、事实图、实体关系图、时间线、伏笔账本和风格样本。生成时按 P0–P4 编译上下文：P0 硬约束永不淘汰，P1 场景相关正史，P2 近章叙事，P3 风格与读者承诺，P4 可选参考。

预算按模型实际窗口动态分配，不再写死 4k token。预算不足时先淘汰 P4–P1；P0 装不下就拆场景，仍装不下就报错停止，绝不静默丢关键事实。V1 先做结构化过滤、实体图、关键词和别名扩展；向量检索作为后续增强，关键事实不依赖向量召回。正史提交、回滚或合并后，相关摘要和索引标记失效并重算。

## Consequences

- 上下文编译器成为核心模块，必须记录来源、淘汰项和编译版本。
- 摘要和索引是派生数据，可重建，不直接当正史事实。
- 语义检索延后到后续阶段，V1 必须先保证结构化检索和关键事实固定可靠。

# 原型是 UI 验收基线

原型不是参考图，而是生产 UI 的验收基线。每个生产页面、动作和状态都必须能对应到原型中的页面/动作；每个 UI ticket 必须引用页面/动作/API 矩阵中的一行。

我们从原型抽取设计令牌和组件清单，生产实现必须映射到这些组件，不允许临时发明样式或交互。每个页面要实现加载、空、错误、禁用、权限不足和长内容状态；固定 1440 / 1180 / 900 / 390 四档响应式验收；用 Playwright 检查壳层、页面根节点、关键动作、状态和溢出。

## Consequences

- UI 交付多一道设计基线门禁，但避免“功能测试通过、界面完全不对”。
- 任何偏离原型的设计必须先更新原型并获得作者签收，再改生产代码。
- Agent UX 新增的本章参考、来源引用、冲突证据和修订差异，也必须先进入原型。

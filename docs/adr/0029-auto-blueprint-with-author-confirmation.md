# 一句话想法自动生成故事蓝图，由作者确认后启用

## Context

当前“一句话想法”创建作品后只建立作品、主创作线和初始版本节点，作者必须分别进入故事圣经、设定中心和大纲手工发起生成。这与“把一个想法长成一本书”的产品承诺不一致，也让新作者在开书后立即面对空页面。

故事圣经、核心设定和初始大纲属于后续生成必须遵守的创作基线。AI 可以起草，但不能替作者决定什么成为已确认设定，也不能在作者确认前直接写入权威故事事实。

## Decision

- “一句话想法”创建作品时，自动创建一个持久化故事蓝图任务，依次生成：
  1. 九卡故事圣经；
  2. 与题材包匹配的核心设定候选；
  3. 全书/分卷路线与首轮章纲、场景卡的初始大纲基线。
- 蓝图生成不生成任何章节正文，也不自动开始第一章。
- 任务在 Worker 中后台执行，页面关闭不取消；完成、失败、等待模型配置和预算暂停均通过站内通知提示。
- API 按题材、规模、章节字数、题材包和当前模型价格给出 token/费用估算，并设置默认预算上限。模型调用前若预计超过上限，任务暂停并保留检查点；作者可以提高预算后继续，或缩小生成范围。
- 蓝图候选与已确认数据分离。候选在作者点击“确认蓝图”前只存在于蓝图草稿中，不能参与正文生成或正史上下文。
- 作者确认是唯一的人工门禁。确认必须满足：
  - 九卡故事圣经完整；
  - 题材包要求的必填核心设定均存在，缺失项由作者明确标记“不适用”并填写理由；
  - 可选缺失项在审阅页显式列出；
  - 没有未处理的 P0 冲突。
- 确认在一个确定性事务链中完成：锁定九卡故事圣经、把核心设定写为已锁定设定、建立初始大纲和计划章节，并写入蓝图确认版本节点。任一步失败时蓝图保持可重试的未确认状态，不能部分对外显示“已确认”。
- 确认后进入作品总览，显示“蓝图已完成”，并提供明确的“开始写第一章”入口；不自动生成第一章正文。
- 空白作品、题材模板、设定导入和旧稿导入保持现有行为；本次自动蓝图只适用于 `mode = "idea"`。
- 蓝图候选、预算暂停和确认状态均按租户隔离；Prompt、正文和私密上下文不进入普通日志。

## Consequences

- 新建作品流程新增一个持久任务、人工审阅页和确认状态机，不再把创建完成等同于创作基线完成。
- 作者会多一次明确确认，但不会在不知情时把 AI 草案当作已确认设定。
- 需要为蓝图审阅页补充原型、UI 合同、作者视觉签收和四档 Golden；在签收前不得实现生产 UI。
- 故事蓝图是“首版故事圣经 + 核心设定 + 初始大纲”的产品集合名，不是新的正史类型，也不替代故事圣经、设定条目或大纲节点的一等模型。
- 初始大纲采用有界基线：完整覆盖全书/分卷路线，并为每个分卷给出首批章纲与场景卡；后续章节由作者在大纲工作台继续细化，不在开书时一次生成整本数百万字章节。

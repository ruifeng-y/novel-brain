# 正史提交与分支合并只有一个门禁模型

每个分支只有一套版本图：分支提交是版本节点，正史提交是带快照的提交节点，章节版本和事实提案是提交节点下的产物。章节审批不等于自动提交所有事实；事实必须单独确认，除非满足明确的自动通过规则。作者确认后，Canon Curator 是唯一提交执行入口，不能自主决定提交。

分支合并和选择性摘取按对象逐项进行：章节、事实、设定、伏笔状态分别检测冲突，由作者逐项确认。人物死亡、金手指升级、已锁定事实、地图/势力根本变化、跨卷主线变更属于不可绕过的高风险门禁。回滚生成新版本，不删除历史；合并、回滚和拒绝都记录原因、操作者和影响范围。

## Consequences

- 技术设计必须统一 branch/canon/version 图，不能保留多套互相竞争的真源。
- 审核后任务需要完整状态迁移：等待审核、批准、驳回、重试、继续和取消。
- 原型的高风险“忽略并继续”必须移除或改成必须记录理由并升级确认。

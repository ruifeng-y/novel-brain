# MVP 是里程碑，不是缩水产品

MVP 可以分阶段交付，但它必须是完整项目的一个垂直切片，不是永久缺功能的替代品。所有 ticket 执行完后，必须得到完整可用的千万字 AI Agent 小说平台：完整正史、上下文、生成、评审、修订、分支、导入、评估、原型一致和安全边界都在范围内。

任何 ticket 不允许以“MVP 先这样、以后再说”为理由留下永久假接口、假交互或缺失的核心能力。可以延后非核心增强（如真实读者数据、自动训练、云厂商适配），但延后项必须明确标记为后续增强，不得影响 V1 核心闭环。

## Consequences

- 拆票时必须先有全量范围，再把 ticket 排成阶段；不能只拆一个残缺 MVP。
- 每张 ticket 的完成定义必须能追溯到最终项目范围。
- “MVP 完成”只是检查点，不是项目完成；所有 ticket 关闭后才是完整项目。

# 开书故事蓝图使用有界基线，不替代全书容量目标

## Context

ADR 0010 冻结了 V1 的最终全书容量：1000 万字、3000–4000 章、30–40 卷。ADR 0029 又要求“一句话想法”在开书时生成可确认的故事蓝图，但明确不一次生成整本数百万字正文或完整章节正文。两者描述的是不同规划阶段；如果不区分，读者会把开书蓝图的少量卷章误认为最终全书规模，或反过来要求首次生成数千章候选。

## Decision

- ADR 0010 继续定义作品最终全书容量和容量验收基线。
- 故事蓝图的 `scaleTarget` 只定义“开书蓝图基线”：`short` 为 1 卷/12 章，`medium` 为 3 卷/36 章，`long` 为 5 卷/60 章，`epic` 为 8 卷/96 章。
- 开书蓝图基线的卷、章、场景数量不代表作品最终规模，也不构成 1000 万字容量验收。
- 作者确认蓝图后，可以继续在大纲工作台扩展后续卷章；系统不得把开书候选自动扩写为整本正文。
- 作者界面、估算和验收文案必须把该范围称为“开书蓝图基线”或“初始大纲基线”，不得称为“全书容量”。

## Consequences

- 现有蓝图估算、Worker 完整性和预算校验可以继续使用 12/36/60/96 章的有界基线。
- 最终全书容量测试、压测和容量证据仍按 ADR 0010 独立执行。
- 若未来要求首次蓝图直接覆盖最终 30–40 卷和 3000–4000 章，必须新增 ADR 取代本决定，并重新设计估算、预算和生成策略。

## 3. 6 项必须先改

### Q034 — 节拍里没有违规句

- 现有节拍：①信未送出；②北境关比旧城晚三十日。
- 实际违规句：「北境关的茶棚里，披斗篷的人却已经念出信中那桩秘事，连末尾的暗记都没有错。」
- 问题：这句话不是必需节拍。只按节拍重写，会得到「信没寄出 + 路程要 30 天」的正常叙述，缺陷消失。
- 建议：把违规句补为第 3 条节拍；同时确认「晚三十日」在这条样本里是**路程时间**，而 Q088 里是**报时鼓时差**，同一句 canon 被读成了两种意思。

### Q055 — 只证明了「顾青不知情」，没证明「沈砚无权知情」

- 原文：「沈砚在顾青尚不知情时，当众说出了**只有作者真相才知道**的身世秘密。」
- 现文：顾青站在门外不知匣里写什么；沈砚当众说出被封存的身世。
- 问题：当事人说出自己的身世，读者不会自动判定为越界。缺的是「沈砚也没有读过名册 / 没有参与问询」这一句。
- 建议：补「沈砚从未打开过那只匣，也没人告诉过他」之类的无权知情句，并写进节拍；否则与 Q158 合并保留 Q158。

### Q067 — 骨折被写成截肢，且「接骨」对断腕不成立

- canon：「身体：左臂骨折尚未痊愈。」
- 现文：「左袖空着，断腕上的布条还渗着血……城头没人替他接骨。」
- 问题一：空袖 + 断腕 = 手已失去，比 canon 的「骨折」严重一级，属于擅自升级。
- 问题二：「接骨」能治骨折，治不了断腕，句子内部互斥。
- 建议：二选一。要么把 canon 改为「左手已失」，要么把正文改回「夹板 / 骨折」（参照 Q196），并删掉「接骨」。

### Q081 — canon 与正文是两件不相干的道具

- canon：「预言：照骨镜会指向真名。」
- 现文：假死旧信 + 说书人提前复述信尾秘密。全文没有照骨镜。
- 问题：样本没有违反它声称违反的那条事实。且「秘密被提前复述」读起来是 knowledge_boundary，不是 foreshadow_payoff。
- 建议：二选一。把正文改成「照骨镜未到冬至祭就显出真名」（与 Q162 区分开），或修正这条样本的 canon 与 family。

### Q084 — canon 不是同一条事实，且船夫句自相矛盾

- canon：「时间：北境关比旧城晚三十日。」
- 现文：「渡口到旧城只有一条山路，往返要十二个小时」+「渡口的船夫仍在等他第一次上船」。
- 问题一：canon 讲北境关时差，正文讲渡口 12 小时，两者不是同一条事实。
- 问题二：既然只有一条山路、他走陆路，船夫为何在等他「第一次上船」？这句旁证与设定冲突。
- 建议：先定这条样本考哪条时间事实；船夫句改为「渡口没人见过他出发」一类自洽旁证，或直接删掉。

### Q123 — 节拍把「伪造」写进了契约

- canon：「分支正史：仅 late-divergence 分支存在的连续性事实。」
- 节拍②：「守祠人翻遍旧稿，发现这行墨迹新得刺眼，前后页却已经发黄。」
- 问题：墨迹新旧是物理证据，读者会读成「有人后来添了一行」= 伪造文书，而不是「晚期分支的结果污染了共同祖先摘要」。缺陷机制被换掉了，而且被写进了必保节拍。
- 建议：正文和节拍都删掉墨迹描写，让那行字「本来就在那里」，才构成分支污染。另确认内容里的「裴照夺舍归来」是否会把样本拉向 identity_transition。

## 7. 跨项系统性问题

1. **审批包缺 `establishedFact` 字段。** 24 项只有 family、严重度、叙事、节拍，没有「要违反哪条既定事实」。审批人无法在本包内验证 canon。建议每项增加该字段。
2. **节拍契约漏掉「缺陷条件」。** 节拍基本只覆盖前两句（设定 + 违规），而「没人替他接骨 / 没有新证据 / 没有新的丹药」这类无因性声明几乎都在第 3 句、不在契约内。Q034 的违规句甚至完全不在节拍里。
3. **风险集中在第 3 句。** 24/24 都是「设定 → 违规 → 补充」三句结构，第 3 句负责机制或旁证，也恰好是 Q075、Q088、Q123、Q149 出问题的地方。不能只看节拍逐字命中就签。
4. **文风换了个模板。** 20/24 含「没有」，13/24 含「也没有」，15/24 用「却」转折。替换解决了「句子重复拼接」，但换成了统一的「事实—却—没有…也没有…」三段式。若 #279 的 hook 门槛要求 ≥3，这批大概率仍是 2。
5. **family / 严重度 / 难度完全共线。** 8 个 family × 3 = 24；P0=12、P1=9、P2=3，与 family 一一对应；难度也一一对应（hard↔P0、medium↔P1、easy↔P2）。分 family 的指标实际是在分严重度。
6. **同 family 三样本同构。** inventory_rights 三条都是「未授权取用」；motivation_drift 三条都是「立誓→为小利背叛→声明无新证据」；foreshadow_payoff 三条都是「未到窗口提前兑现」。24 条全为仙侠，只用了沈砚/顾青/裴照/闻雪四个角色和六件道具。
7. **结构上只能有一个签字人。** `approval-request.md` 第 20–21 行：一条评论、一个作者，且「每个 adjudicatorId 必须等于评论作者」；`humanAttestation.author` 也是单值。若预期多人分工，当前设计表达不了。
8. **24/24 全有或全无。** 任一项 reject 就整体不能冻结。以现在 6 项待改的状态，门禁会卡死。建议先迭代到 24 项无阻塞，再做一次性 attestation。
9. **本地无法验证 packet / manifest / payload。** 目录内没有 candidate packet、replacement manifest，也没有 `package.json`，`pnpm quality:clean-packet -- --payload-hash` 无法在此运行；三个头部 hash 目前只能相信、不能复算。
10. **旧分数文件仍在同目录。** `reviewer-0x-scores.completed.csv` 里仍有这 24 个样本的旧分数。#279 若全量重评，需按 sample ID + packet version 排除，而不是按文件排除。

## 8. 修改的连锁影响

任何一处文本或节拍修改都会依次改变：

`replacementTextSha256` → `requiredBeatsSha256` → `manifestEntrySha256` → `replacementManifestSha256` → `candidatePacketSha256` → approval payload hash。

同时 `humanAttestation` 里的 packet hash、manifest hash、comment 正文都要重发。

**当前 0 人签字，是唯一低成本的修改窗口；一旦有人签了第一项，已签内容全部作废。**

建议顺序：

1. 修 6 项硬问题，裁定 11 项；
2. 重算 5 个 hash，重新冻结 packet / manifest；
3. 把 packet、manifest 一并放进审批目录，使 hash 可复算；
4. 24 项无阻塞后，由同一位真实负责人一次性填写 7 个字段并发布 attestation；
5. 发布前用第 1 节的口径复算一遍 payload。

## 2. 本轮关闭的 P0

- 需求章节状态 5 态与 ADR 8 态冲突。
- 章节批准、事实确认和故事事实提交混用。
- 工作台回收站可直接永久删除。
- 黄金三章六维未达标仍可锁定。
- 导入报告存在未裁决冲突仍可进入总览。
- 锁定档案仍可直接添加别名或接受设定提案。
- 原型残留“单一版本图”“上下文包”“淘汰记录”“P0–P4”等内部术语。
- 同页样例同时出现“少年出山 / 血河夜行”和“1–100 / 31–60”卷号冲突。
- 9 个页面仍使用通用状态占位。
- Playwright 使用绝对路径和本机 Edge，无法直接进入 CI。

## 3. 明确留到后续

- `/to-tickets` 生成前，117 个能力保持 `unmapped`；ticket 生成后必须全部映射，不能继续留空。
- 原型只提供静态交互和模拟数据，真实后端长列表、权限、部分成功和断点恢复由实现阶段验证。
- 当前有截图基线，但未启用像素级视觉 diff；若后续 UI 频繁变动，再增加稳定的视觉回归门禁。
- 需求和技术正文的字段级 DTO、表约束、接口样例由 `/to-spec` 展开，不在本基线继续膨胀。

## 4. 下一步

进入 `/to-spec`，按 M0–M3 里程碑拆垂直切片；所有 V1 能力最终都必须被 ticket 覆盖。M0 可以窄，但整个 V1 不允许缩水。

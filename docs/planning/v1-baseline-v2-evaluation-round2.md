# V1 Baseline Sync v2 评估 · 第二轮复查

> 日期：2026-11-04
> 范围：需求、技术设计、ADR 0010–0023、原型、能力清单、Playwright
> 结论：**本轮发现的 P0/P1 已全部关闭。复审通过，可以进入 `/to-spec`。**

## 1. 复查结果

仍然成立的部分：

- 1000 万字、3000–4000 章、30–40 卷的规模基线一致。
- 章节 8 态、单一版本图、审核三段动作在需求和技术设计中已对齐。
- 117 个能力 ID 在 Manifest 与 Traceability 中一一对应，无重复、无缺失。
- 复查时 Playwright 46 项通过；修复后 49 项通过，72 张 18 页 × 4 档截图已重生成。
- 原型内部术语扫描干净，页面状态文案已覆盖 18 页。

但以下问题会使实现阶段再次偏离基线。

## 2. P0 问题

### P0-1 事实确认仍直接写入已确认设定（已修复）

原型中点击事实“确认”或“修改后确认”后，修复前会直接提示“已写入已确认设定”：

- `prototype/app.js` 的 `decideFact`
- `prototype/index.html` 的批量审核提示

这绕过了 ADR 0017 的三段状态机：

1. 批准章节。
2. 确认事实。
3. 满足条件后执行故事事实提交。

原型没有独立的“提交本章事实”动作，也没有“章节未批准时不能提交”的门禁。

### P0-2 缺少“部分/完整设定导入”入口（已修复）

核心需求要求作者可以从自己的部分或完整设定开书：

- `docs/requirements/v1-requirements.md:155`
- `docs/planning/v1-capability-manifest.md:33` 的 WORK-001 明确写“四种入口 E2E”

但原型的“新建作品”只有：

- 一句话想法
- 空白作品
- 题材模板
- 导入旧稿

没有“导入部分/完整设定”入口，也没有设定导入后的候选映射、冲突处理和确认步骤。旧稿导入不能替代设定导入。

## 3. P1 问题

### P1-1 里程碑体系冲突（已修复）

- 需求使用 `M0–M3`：`docs/requirements/v1-requirements.md:701`
- 技术设计使用 `P0–P5`：`docs/technical/nestjs-backend-design.md:957`

两套编号没有映射，且 `P0–P4` 又与上下文优先级和缺陷等级重名。`/to-spec` 和 `/to-tickets` 会无法判断一个能力属于哪个交付里程碑。

### P1-2 原型签收状态自相矛盾（已修复）

- 复查开始时，评估结论写“可以进入 `/to-spec`”，但原型合同和 README 仍写“最终作者签收未完成”。

ADR 0012 规定原型修正并签收后才能作为 UI 验收基线。没有明确签收记录，不应把原型视为完成验收。

### P1-3 原型状态矩阵仍是旧内容（已修复）

原型状态矩阵仍显示旧状态和“缺口”，例如“七态全局演示”“缺加载、错误、长列表”。这与当前 18 页专属状态和 11 类状态面板不一致，会误导后续 UI 实现。

## 4. 非阻塞项

- 117 个能力仍为 `unmapped`，这是 `/to-tickets` 前预期状态。
- 当前是截图基线，没有像素级视觉 diff。
- Manifest 标题仍为 v0，Traceability 为 v1；版本号应统一但不会改变能力集合。

## 5. 修复顺序

1. 在新建作品加入“设定导入”：支持部分/完整设定，展示识别结果、候选、冲突和确认。
2. 拆分事实动作：确认事实只改变事实状态；新增“提交本章事实”，并强制章节批准条件。
3. 统一交付阶段：把技术设计的 P0–P5 改为 B0–B5 或直接映射到 M0–M3。
4. 更新原型状态矩阵和签收状态，补作者签收记录。
5. 重跑 Playwright、72 张截图和第六轮复查。

## 6. 修复记录

- P0-1：事实确认只改变事实状态；新增“批准本章”和“提交本章事实”两个动作，提交门禁为 `章节已批准 + 无待确认事实`。
- P0-2：新建作品新增“导入设定”，支持部分/完整设定、候选识别、冲突裁决和确认门禁。
- P1-1：技术设计构建阶段改为 `B0–B5`，明确映射到产品里程碑 `M0–M3`。
- P1-2：新增 `docs/ui/v1-prototype-signoff.md`，原型合同和 README 已统一为已签收。
- P1-3：18 页状态矩阵改为当前真实状态和证据，不再保留“七态”“缺口”旧文案。

## 7. 裁决

Baseline Sync v2 已完成。Playwright 49 项通过，72 张截图已重生成，可以进入 `/to-spec`。

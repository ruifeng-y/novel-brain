# 长线创作采用受控多代理

NovelBrain 采用“确定性编排器 + 有边界的创作代理”，而不是自由 Agent 或单一超长提示词。编排器控制步骤、预算、检查点、重试和人工确认点；代理只承担单一职责，只能读写被授权的数据，任何代理都不能直接提交正史。

这样做的原因是：千万字级作品无法整体放进模型上下文，单次提示词也无法同时完成规划、写作、连续性校验和文风打磨；完全自主 Agent 又不可复现、不可审计。受控多代理把“谁负责什么、谁能改什么、什么时候必须停下来找作者”变成明确契约。

## Consequences

- 单章生成会从一次模型调用变成多个有边界的步骤，成本和延迟上升，但每一步都能解释、重试和回放。
- Writer 只能看到上下文包；Critic 只能输出结构化问题；Reviser 只能定向改草稿。
- 只有 Canon Curator 能在人工确认后提交正史。
- Canon Curator 是唯一提交执行入口，不是自主决策者；没有作者确认或明确的自动通过规则时不能提交。
- 草稿可以并行，正史提交必须串行；全本按卷拆子任务，卷末必须人工验收。
